# Telegram-бот для сети закрытых каналов

Стек: **Python 3.11+, aiogram 3, aiosqlite**.

## Установка

```bash
pip install -r requirements.txt

export BOT_TOKEN="ваш_токен_от_BotFather"
export ADMIN_IDS="123456789,987654321"   # ваш Telegram user_id через запятую

python main.py
```

## Предпросмотр приветственного поста

И в конструкторе цепочки (пока добавляете сообщения), и в уже сохранённой
карточке канала есть кнопка **👀 Посмотреть пост** — бот пришлёт вам в личные
сообщения всю цепочку целиком, как её увидит подписчик (с клавиатурой замка,
если он включён), без ожидания настроенных задержек между сообщениями.

## Удаление канала из сети

В карточке канала (`📡 Каналы сети → выбрать канал`) есть кнопка **🗑 Отключить
канал** — с подтверждением. Она полностью чистит всё, что связано с каналом:
его реф-ссылку, приветственную цепочку и её шаги, упоминания этого канала как
условия в чужих замках, ссылки на него как на канал-награду (в таких цепочках
замок просто выключается) и историю поданных заявок.

Дополнительно бот пытается убрать канал из реестра автоматически, если получит
от Telegram апдейт о том, что потерял к каналу доступ (кикнут/покинул). Но
учтите: **при полном удалении канала владельцем Telegram не всегда присылает
такой апдейт** — тогда канал в списке бота останется «осиротевшим», и его нужно
убрать вручную той же кнопкой 🗑.

## Если канал не подключился автоматически

`my_chat_member` иногда не долетает до бота — например, если бота добавили в
канал администратором ещё до первого запуска процесса, или платформа не
доставила update. В этом случае в `/admin → 📡 Каналы сети → ➕ Добавить канал
вручную` есть два запасных способа:

- **📨 Переслать пост из канала** — бот сам определит канал-источник из
  пересланного сообщения (не сработает, если в канале включена «скрытая
  пересылка» — тогда источник не виден вообще).
- **🆔 Ввести ID канала** — работает всегда, если знаете ID (обычно вида
  `-1001234567890`, узнать можно через @userinfobot).

В обоих случаях бот дополнительно проверяет через `get_chat_member`, что у
него есть права администратора в канале, и предупреждает, если прав нет.

## Как настроить сеть каналов

1. Добавьте бота в каждый канал сети **администратором** с правами:
   «Управление заявками на вступление» и «Приглашение пользователей по ссылке».
   Как только это произойдёт, канал сам появится в разделе `/admin → 📡 Каналы сети`
   (это и есть «автоматическое пополнение списка каналов» из ТЗ).
2. Откройте канал в списке → **🔗 Создать реф-ссылку**. Бот сам сгенерирует
   пригласительную ссылку через Bot API (`creates_join_request=True`) — именно
   её вы и раздаёте как реферальную/промо-ссылку на канал.
3. В том же канале нажмите **✉️ Настроить приветствие** — конструктор цепочки:
   добавляйте посты (текст/фото/видео/кружочек/голосовое/документ) по одному,
   к каждому указываете задержку перед отправкой. HTML-форматирование,
   вшитые ссылки и медиа сохраняются как есть.
4. По желанию — **🔒 Обязательная подписка**: отмечаете каналы-условия и
   канал-награду. Пользователь получит одноразовую ссылку на канал-награду
   (`member_limit`-эквивалент через `creates_join_request` + отзыв ссылки после
   одной заявки) только когда подаст заявки во все каналы-условия.
5. Сохраняете — цепочка включается и с этого момента отправляется каждому,
   кто подаёт заявку в канал.

## Технические решения, о которых стоит знать

- **Отправка ЛС без /start у бота.** Update `chat_join_request` в Bot API 6.5+
  содержит поле `user_chat_id`, специально предназначенное для того, чтобы бот
  мог написать пользователю личное сообщение сразу после заявки, даже если тот
  не запускал бота. Именно это поле и используется.
- **«Одноразовая» ссылка в канал-награду.** Telegram не разрешает одновременно
  `member_limit` и `creates_join_request` у инвайт-ссылки, а по ТЗ ссылка должна
  вести именно на подачу заявки (не мгновенный вход). Поэтому ссылка создаётся
  с `creates_join_request=True`, а после первой же заявки по ней бот сам её
  одобряет и **отзывает** (`revokeChatInviteLink`) — второй раз ей воспользоваться
  нельзя.
- **Антифлуд-очередь** (`utils/flood_queue.py`): если пользователь почти
  одновременно подал заявки в несколько каналов сети, первое приветствие уходит
  мгновенно, все следующие — через 2.5 минуты (настраивается в `config.py`,
  `flood_delay_seconds`), чтобы не спровоцировать антиспам Telegram.
- **Определение канала по реф-ссылке.** Bot API не даёт методов «узнать chat_id
  по произвольной ссылке-приглашению» — это ограничение платформы, а не бота.
  Поэтому канал регистрируется по событию «бота сделали админом» (`my_chat_member`),
  а реф-ссылка генерируется самим ботом через `createChatInviteLink` — это даёт
  тот же результат (уникальная рабочая ссылка на канал), но надёжно.

## Структура проекта

```
config.py            — токен, админы, настройки
database.py           — aiosqlite: схема и все запросы
keyboards.py          — инлайн-клавиатуры с эмодзи
states.py             — FSM-состояния конструктора цепочек
utils/flood_queue.py  — антифлуд-очередь отправки
utils/chain_sender.py — последовательная отправка цепочки с задержками
handlers/
  membership.py        — авто-регистрация каналов
  join_request.py       — ядро: обработка заявок, замок, антифлуд
  user_callbacks.py     — кнопка «Проверить подписку»
  admin_menu.py          — /admin и главное меню
  admin_channels.py     — список каналов, генерация реф-ссылок
  admin_welcome.py      — конструктор приветственной цепочки + замок
main.py               — сборка и запуск
```

## Что стоит доработать под продакшн

- Хранение `admins` сейчас дополняет `ADMIN_IDS` из окружения — добавьте команду
  `/addadmin`, если нужно управлять списком без перезапуска.
- Для нагрузки от 10+ каналов и большого потока заявок рекомендуется вынести
  `aiosqlite`-соединение в пул или перейти на PostgreSQL — SQLite отлично
  подходит для старта, но пишет из одного соединения последовательно.
- Повторный вход в конструктор **дописывает** новые шаги к уже существующим
  (старые не удаляются). Если нужна возможность начать цепочку с нуля —
  добавьте кнопку «🗑 Очистить», вызывающую `db.clear_chain_steps(chain_id)`.
